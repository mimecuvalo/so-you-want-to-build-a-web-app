# JS, ahem, I mean TS for newbies

despite the image at the top of this section, i ❤ javascript (typescript) so hard (tbh, typescript has taken over!). i’ve been coding in it since the 90’s and it’s only gotten better over the years.

if you’re absolutely new to JS, start [here](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide) at the Mozilla Developer Network (or MDN). they’re the people that make Firefox and have the best reference guides for JS. in general though this guide assumes you’ve got a base understanding of JS so go forth and mess around with the language as much as you can before moving on to the rest of the more complicated stuff.

to learn the basics of TS i can recommend checking out the [Concise TypeScript Book](https://gibbok.github.io/typescript-book/).

## playgrounds

an easy way to get started is by checking out some of these tools that let you play around with the language. another great way is to a project that you like and checking out it’s code. view the source, luke!

* **[CodeSandbox](https://codesandbox.io/s/new)**: lets you mess around with a React app in real-time.
* **[CodePen](https://codepen.io/)**: a social development environment for front-end designers and developers.
* **`bun`’s** **[REPL](https://bun.com/docs/runtime/repl)**: most coding environments provide something called a REPL which lets you mess around with the code on the command line. just type in `bun repl` on your command line and you should be able to try out some random code.
* **[RunKit](https://runkit.com/home#notebooks)**: much like node’s REPL but online with some fancy UI.
* **npm sandboxing**: you can take any package from [npm](https://npmjs.com) and play around with it to see what it does:

```sh
mkdir sandbox
cd sandbox
npm init -y       # create an npm project. -y means use defaults
npm install --save <package name>
```

# react + (meta) friends

let’s get something straight: vanilla JS is something you absolutely should know. you need to understand the underlying principles and fundamentals of the frameworks you’ll be using so that you can effectively use them.

that being said, practically speaking, you won’t be writing vanilla JS a lot of the time and a well-chosen suite of frameworks will help immensely in your quest. a lot of the best of breed frameworks have come from a Cambrian explosion emanating from Meta's developer team. Google has tried through many, many, iterations to provide compelling alternatives but we should have seen the downward trend with frameworks ever since they started with the ill-conceived [GWT](https://en.wikipedia.org/wiki/Google_Web_Toolkit). (i say this with love, y’all, since i used to work at Google. their contributions to browser tech and tools are amazing, but their frameworks have always been lagging.)

there are other competitors in this space and while i do *highly* recommend React down below, there is something to be said about React starting to lose the plot these days (in particular with RSC, or, React Server Components).
for an interesting take on this you can read: [React Won by Default – And It's Killing Frontend Innovation](https://www.lorenstew.art/blog/react-won-by-default)

let's read on!

## [React](https://react.dev/)

*the* way to write your application these days. if there’s one place to make sure you devour all the documentation, it’s here. go through the tutorials and starter guides (using [`create-next-app`](/javascript#create-next-app), mentioned in a section of its own below, is also a good leg-up.)

**[JSX](https://reactjs.org/docs/introducing-jsx.html)**
a compelling feature that comes bundled with React is it’s ability to describe HTML and custom components *within* JS itself. this was high heresy not long ago (much like CSS-in-JS is still heresy in lots of circles but gaining traction.)

an example:

```js
const element = <h1 className="greeting">Hello, world!</h1>;
```

underneath the hood, the code will be transformed into:

```js
const element = React.createElement(
  'h1',
  {className: 'greeting'},
  'Hello, world!'
);
```

**tips**

* you don’t need to `import React` anymore directly with version 17+ to get JSX working.
* adding `React.StrictMode` to your tree can help you with migrations.

## `<strike>`React Redux`</strike>`

probably the more cultish side of the React-verse 😛. you’ll find a lot of acolytes and haters here. i actually might not recommend Redux for you, at least not off the bat. it’s another one of those mind-bending parts of the React world that can be a lot to take in. besides, even the creator suggests that sometimes [it can be unnecessary](https://medium.com/@dan_abramov/you-might-not-need-redux-be46360cf367).

## [React Native](https://facebook.github.io/react-native/)

allows you to build native mobile apps using React. i don’t have much experience here but i hear good things and that it’s getting better over time. related libraries that are of interest: [Expo](https://expo.dev/), [Yoga](https://yogalayout.com/), [Flutter](https://flutter.io/). a great starter library is [Tamagui](https://tamagui.dev/).

# [`bhvr`](https://bhvr.dev/)

there’s a lot that goes into a javascript app these days. *a lot*. to that end, we’re gonna use the [`bhvr`](https://bhvr.dev/) template to quickly get set up. [`bhvr`](https://bhvr.dev/) helps bundle together: [Bun](https://bun.dev/), [Hono](https://hono.dev/), [Vite](https://vite.dev/), [React](https://react.dev/) which gets you going with most of your basic needs in an app.

the `bhvr` acronym stands for:

* **b**un: fast javascript runtime & toolkit
* **h**ono: web application framework, a lightweight API backend basically.
* **v**ite: build tool.
* **r**eact: and the frontend framework.

## installation

first, make sure you have [`bun`](https://bun.com), which is a JavaScript runtime:

```sh
curl -fsSL https://bun.com/install | bash
```

the previous recommendation here was [`node`](https://nodejs.org) but my favor has gone to Bun these days. **keep on eye on**: [Deno](https://deno.com/)

installing `bhvr`:

```sh
bun create bhvr@latest
cd <name-of-your-new-project>
bun run dev
```

as an alternative, for this guide, i have my own opinionated template of `bhvr` combined with TanStack Start called [`all-the-things`](https://github.com/mimecuvalo/all-the-things).

# security

as mentioned in [+🛠️ tools of the trade: security](/tools-of-the-trade#security), every engineer is a security engineer. you need to act like it and protect your app from the forces acting against you.

in addition to the protections at the server level, there are some things to implement at the application level as well. this is called “[defense in depth](https://en.wikipedia.org/wiki/Defense_in_depth_\(computing\))”, adding multiple layers of security to protect yourself.

* **escaping user data** (via **React)**: the easiest, most common mistake is taking user-submitted data to your site and spitting it out somewhere else. a user can easily submit malicious HTML/JS that would then attack other users on the site. you can take a great stride to avoiding this by using a framework, like React, that escapes user data by default.
* **data validation**: i can’t recommend a particular framework/library here but you should take care to validate that the data you get from your users is what you expect it to be. if you’re expecting a date like `10/12/2012` but instead get `alert(1)` you should call shenanigans.
* **[bcrypt](https://en.wikipedia.org/wiki/Bcrypt)**: if you need to deal with passwords on your site, this library should be in your toolset.
* **[reCAPTCHA](https://www.google.com/recaptcha/intro/v3.html)**: if you need to deal with bots, this tool from Google will help [prove if you’re a robot or not](https://youtu.be/en5_JrcSTcU?t=337).
* **npm package security**: you never really know what possibly malicious code you’re pulling in to your repository via npm. one way to help combat this attack vector is using exact versioning. set this by doing `npm config set save-exact true`
* **[subresource integrity](https://developer.mozilla.org/en-US/docs/Web/Security/Subresource_Integrity)**: when including external scripts, you can add a hash via the `integrity` attribute. this verifies that the script hasn’t changed behind your back.

fun articles to read (to make you more paranoid):

* [I’m harvesting credit card numbers and passwords from your site. Here’s how.](https://hackernoon.com/im-harvesting-credit-card-numbers-and-passwords-from-your-site-here-s-how-9a8cb347c5b5)

# libraries of interest

if there’s one thing that will last after the earth is gone, it’ll be cockroaches and js libraries. there are *so many* of them. try not to overdo it, because with each library you add, you become beholden to it.

**some brief recommendations, as of 2023**

* ***not*** **jQuery**. jQuery has served the JS community well over the years but its time is passed. avoid.
* **[lodash](https://lodash.com)/[es-toolkit](https://es-toolkit.dev/)**: two handy libraries to help manipulate data structures among other capabilities. historically this was provided by `underscore`.
* **[classnames](https://www.npmjs.com/package/classnames)**: i know, this is a tiny library compared to the other ones but so handy. helps with setting classes conditionally for an element.
* **[react-intl](https://github.com/yahoo/react-intl/wiki#getting-started)**: internationalization (i18n).
* **[Jest](https://jestjs.io/)** / **[Vitest](https://vitest.dev/)**: testing libraries.
* [oxlint + oxfmt](https://oxc.rs/): speedy as hell tooling.
* **[Socket.io](https://socket.io/)**: provides a persistent, real-time connection client ↔ server. alternatively, i hear good things about [SockJS](https://github.com/sockjs/sockjs-client).
* **[Hammer.js](https://hammerjs.github.io/)**: provides touch gesture (mobile) support for your app.
* **[Luxon](https://moment.github.io/luxon/)** **([Temporal](https://tc39.es/proposal-temporal/docs/cookbook.html)** **soonish)**: date/times are surprisingly complicated. this library manages that. used to be Moment.js. the next *native* library to watch out for here is [Temporal](https://tc39.es/proposal-temporal/docs/cookbook.html).
* **[immer](https://immerjs.github.io/immer/)**: in case you need immutability with your data objects
* **[Stripe](https://stripe.com/)**: ecommerce/payments.
* **[PostHog](https://posthog.com/)** (maybe [Highlight](https://www.highlight.io/)?): analytics.
* **[Tina](https://tina.io/),** **[Sanity](https://www.sanity.io/),** **[Payload](https://payloadcms.com/),** **[DatoCMS](https://www.datocms.com/),** **[Builder](https://www.builder.io/)**[:](https://www.builder.io/) CMS — lots of options, i think Tina is doing something interesting, albeit pretty scrappily.
* **[crawlee](https://crawlee.dev/),** **[puppeteer-heap-snapshot](https://www.adriancooney.ie/blog/web-scraping-via-javascript-heap-snapshots)**: scraping.
* **[tesseract.js](https://tesseract.projectnaptha.com/)**: OCR.
* **[react-hook-form](https://react-hook-form.com/)**: forms.
* **[driver.js](https://driverjs.com/)**: onboarding UI.
* **[GitHub Actions](https://github.com/features/actions),** **[Trigger](https://trigger.dev/)**: cron.
* **[pino](https://www.npmjs.com/package/pino)**: logging.
* **[sandworm](https://sandworm.dev/),** **[socket](https://socket.dev/)**: security.
* **[zod](https://zod.dev/)**: schema validation.

**other notes**

* by the way, there are other libraries smattered throughout this guide (e.g. [Material-UI](https://material-ui.com/)) but those are more frameworks to “buy into” vs. handy tools that you can pull into a particular file.
* to create your own libraries, there exists [create-react-library](https://github.com/transitive-bullshit/create-react-library) and its companion repository, [react-modern-library-boilerplate](https://github.com/transitive-bullshit/react-modern-library-boilerplate).
